Daemon 發現、生命週期與版本切換

點按操作，感受「每位使用者一個 Daemon」在正常啟動、版本衝突、重啟與 crash 復原時應如何保護其他 Origin Session。

PROTOTYPE — 純記憶體模擬，不會啟動程序、連網或寫入資料庫
這份原型要回答的問題 `open-connect` 如何發現並重用同版本 Daemon；遇到不同版本時如何 fail closed；只有在明確 drain/restart 後才切換版本；以及 crash 後如何以 durable journal 恢復 `received` Event、等待同一 Agent Connection rebind、重播 Feedback，而不另開 Origin Session？

建議的 v1 預設

按需啟動不做 OS login auto-start。第一次 `open-connect` 才啟動；零連線且無待投遞工作 15 分鐘後關閉。
SQLite-style journal單一 DB、WAL、`synchronous=FULL`；Receipt／Feedback 先 commit，再回應或推 SSE。
期限delivery 120 秒、rebind grace 30 秒、drain 30 秒。Origin 離線不排隊。
保留terminal Event Receipt、Feedback 與 tombstone 保留 7 天；同一 `eventId` 於保留窗內去重。
state dirUnix 目錄 `0700`／檔案 `0600`；Windows current-user-only DACL。
復原檢查 stale marker → WAL recovery → 同 `connectionId` rebind；逾期即 `origin_offline`，不 cold resume。
